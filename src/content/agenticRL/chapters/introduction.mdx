## Introduction

Agentic RL 的目标是训练 agent 使用 tools，以最大化完成任务的能力：

1. SFT: 模仿学习，避免模型出现低级的工具调用错误
2. RL: 让模型探索并强化有效轨迹

要解决的问题：

1. 高质量的可验证训练数据
2. 怎样将可验证的数据有效地喂给模型

Scaling agentic RL 面临的系统瓶颈：

1. large scale sandbox environment
2. long context inference: 128k-1M, 50~100+ turns
3. long context training
4. agent harness RL: memory, tool, subagent, etc

agentic AI 的下一个瓶颈是 system scaling，而不只是 model scaling：

- model scaling: parameters, data, compute
- system scaling: memory, retrieval, tools, skills, verification, policy

相对 [RLHF](https://maosong.website/blog/RLHF/) / [RLVR](https://maosong.website/blog/RLVR/)，Agentic RL 的本质差异在于 turn-level 决策、long-horizon 交互，以及稀疏的可验证 outcome reward。后文按「Introduction（Agent / 形式化 / 挑战）→ Data / Infra → Methods → Recent Progress」展开；实践上，agent RL 往往是 environment > reward > algorithm，而 reasoning RL 更接近 algorithm > reward > environment。

### Agent

Agent 定义为

<Quote source="Simon Willison, <a href='https://simonwillison.net/2025/Sep/18/agents/'>">
  An LLM agent runs tools in a loop to achieve a goal.
</Quote>

agent 的核心能力：

1. accurate tool calling
2. coherence over long context
3. customizability
4. complex task management
5. environment understanding
6. safety

提升模型的这些能力有两条路径：

1. LLM training
2. harness engineering

| Capability                  | Harness                                                                              | Training                                                               |
| --------------------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| accurate tool calling       | grammar-constrained decoding                                                         | SFT on tool-calling traces                                             |
| coherence over long context | 1. context compression/compaction; 2. dynamic memory lookup; 3. sub-agent delegation | SFT on long context                                                    |
| Customizability             | agent memory; skills; custom tools                                                   | RLHF                                                                   |
| Complex task management     | provide planning/decomposition tools;sub-agent delegation                            | train on complex/long horizon tasks                                    |
| environment understanding   | learn skills corresponding to domain knowledge                                       | SFT on data with expected observation shape; RL on domain specific-env |
| safety                      | sandbox tools; limit access to credentials; monitor trajectories                     | safety aware RL                                                        |

#### Paradigm

ReAct-style 中，agent 与 environment 交互过程定义如下：

给定 query $q$, system prompt $s_0$, tool metadata $\mathcal{T}_{\mathrm{meta}}$, agent 通过 reasoning 产生 action 与环境进行交互, 这个交互过程产生一个轨迹 $\mathcal{H}_{T}$

$$
\mathcal{H}_{T}:= \{(q,s_0,\mathcal{T}_{\mathrm{meta}}),(r_1,a_1,o_1),\dots,(r_i,a_i,o_i),\dots,(r_T,a_T)\}
$$

其中 $r_i,a_i, o_i$ 分别代表 reasoning CoT, action 和 observation, $a_T$ 是最终回答。给定 $t\leq T$, agent $\pi$ 基于历史交互信息 $\mathcal{H}_{t-1}$ 生成 reasoning CoT $r_t$ 和 action $a_t$,

$$
r_t,a_t \sim\pi(\cdot\mid \mathcal{H}_{t-1})
$$

environment $\mathcal{E}$ 基于 action $a_t$ 返回 observation $o_t=\mathcal{E}(a_t)$, 然后更新轨迹

$$
\mathcal{H}_{t} = \mathcal{H}_{t-1}\cup (r_t,a_t,o_t)
$$

### Formulation

Agentic RL 解决的任务可以定义为一个 partially Observable Markov Decision Process (POMDP)。

一个 POMDP 由 tuple $(\mathcal{S},\mathcal{A},\mathcal{T},\mathcal{R},\Omega,\mathcal{O}, \gamma)$ 确定，其中：

1. $\mathcal{S}$ 是状态空间
2. $\mathcal{A}$ 是动作空间
3. $\Omega$ 是 observation, 是状态空间的部分描述
4. $\mathcal{T}:\mathcal{S}\times\mathcal{A}\to\mathcal{S}$ 是状态转换函数
5. $\mathcal{R}:\mathcal{S}\times\mathcal{A}\to\mathbb{R}$ 是 reward function

在 agentic 场景下，模型输入为一个 task prompt $s_0$，与环境交互后产生轨迹

$$
\tau=(s_0,a_0, o_0,r_0, s_1, a_1,\dots,a_{T-1}, o_{T-1}, r_{T-1}, s_T)
$$

agent $\pi_{\theta}$ 从 action space 采样得到 $a_t\sim\pi_{\theta}(\cdot\mid s_t)$，这里 $a_t=(a_t^1,a_t^2,\dots,a_t^{<eos>})$ 是按自回归方式生成的 token sequence，即 $a_t^i\sim\pi_{\theta}(\cdot\mid s_t,a_t^{<i})$；$o_t$ 是执行 $a_t$ 后环境返回的观测，环境给予奖励 $r_t=\mathcal{R}(s_t,a_t)$ 并更新状态 $s_{t+1}\sim \mathcal{T}(s_t,a_t)$ $o_t$ 是 agent 对于 $s_{t}$ 的一个观测，当 $o_t=s_t$ 时，POMDP 退化为 MDP.

与 reasoning RL 相比，Agentic RL 的状态、动作与转移都发生了本质变化：

| Paradigm                  | reasoning RL            | agentic RL                       |
| ------------------------- | ----------------------- | -------------------------------- |
| state                     | context $(y_{<t},x)$    | context, environment observation |
| action                    | token $y_t$             | complete response at turn $t$    |
| transition                | concatenation           | stochastic depends on tool use   |
| reward                    | terminal state          | terminal state                   |
| horizon                   | 1 turn, 0.5k-30k tokens | 10-100 turns, 100k-1M tokens     |
| action type               | tokens, homogeneous     | tool, plan heterogeneous         |
| intermediate verification | possible                | rarely possible                  |

| Method      | RLVR/RLHF    | Agentic RL                |
| ----------- | ------------ | ------------------------- |
| Granularity | token        | turn                      |
| Action      | token        | tool call / turn response |
| horizon     | short        | long                      |
| State       | MDP (approx) | POMDP                     |

### Core Challenges

Agentic RL 相比 RLHF / RLVR 有三个核心挑战：

1. **Granularity mismatch**: 决策的自然单位从 token-level 转向 turn-level。agent 的一次交互包括 observation、reasoning、tool call、tool result；单个 token 不独立面对环境，也不会收到反馈。因此 agentic RL 与 RLHF/RLVR 存在 granularity mismatch：后者比前者细两三个数量级。
2. **Long-horizon tasks**: agentic rollout 动辄几十步、上万到数十万 token，很难做 credit assignment；由于 discount 的存在，初始 token 衰减严重，而早期决策往往又最关键。
3. **Sparse outcome reward**: agentic tasks 通常只有任务成功/失败信号。GRPO [@DeepSeek-Math] 让一条 rollout 内所有 token 共享 advantage；在 agentic 场景下，这会显著降低数据使用效率。

用 GRPO 直接做 agentic RL 的问题：一条成功 rollout 里也有无效动作，一条失败 rollout 里也有高质量动作，但 episode-level outcome 会「凭结果论英雄」。本质上是把 multi-turn 当成 single-turn，仅用 outcome reward 打分，整个 rollout 变成一个单一决策步。

为什么需要更细的 credit assignment：

1. reasoning RL: 10k~30k tokens（例如 DeepSeek-R1 在 AIME2025 上平均输出约 23k tokens）。episode-level 方法对每个 token 使用相同 advantage。
2. agentic RL: 10~100 turns，总 token 数 100k~500k（如 SWE-bench 平均约 131k tokens、64 turns）。episode-level 方法可能给一个错误工具调用和三个正确工具调用相同的奖励。

除此之外，Agentic RL 还面临：

1. 环境转移是随机的
2. 部分可观测（POMDP）
3. vastly longer horizon
4. heterogeneous action types
5. non-verifiable intermediate states
6. The Bifurcation Point Problem

对 agent RL，优先级通常是 environment > reward > algorithm。环境与 reward 准备好之后，再做数据和算法消融更有意义；同时需要稳定的工具调用训练环境，并对齐训练与评测环境。工具层面的探索会影响能力上限；更大模型的 RL 泛化通常更好；continue RL 往往更依赖高质量数据，而不只是 trick。
