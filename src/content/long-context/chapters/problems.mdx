### 先区分三种“长度”

讨论 long context 时，至少需要区分以下三个量：

| 概念 | 回答的问题 | 能说明什么 |
| --- | --- | --- |
| 上下文窗口长度 | 单次请求允许容纳多少 token？ | 输入与生成的总预算 |
| 有效上下文长度 | 模型能在多远的位置可靠找到并使用信息？ | 与任务、信息位置和干扰程度相关的实际能力 |
| 流式处理总长度 | 模型能连续处理多久而不重置？ | 持续运行能力，不代表全部历史仍可访问 |

例如，一个系统可以用固定大小的缓存连续处理数百万 token，却只能直接访问最近一段内容。另一个模型可以接收很长的输入，但仍可能漏掉远处的关键信息。因此，长上下文不能只用一个窗口数字衡量。

### 位置外推：能计算新位置，不代表能泛化

RoPE 可以为任意位置计算旋转角度，但模型通常只在有限长度的序列上训练。输入超过训练长度后，部分位置关系落到训练分布之外，直接外推可能导致语言建模性能下降。PI 与 YaRN 等方法通过修改位置或频率来缓解这个问题。[@PI; @YaRN]

位置扩展还面临局部与全局的权衡：如果把所有位置间距一起压缩，远处 token 可以落回较熟悉的范围，但相邻 token 的位置差异也会变小。如何保留局部细节，是不同 RoPE 扩展方法的主要分歧。

### 资源开销：完整注意力与 KV cache 都会增长

设序列长度为 $n$、注意力头维度为 $d$，标准完整注意力的核心计算量为 $O(n^2d)$。直接物化注意力矩阵还会产生 $O(n^2)$ 的中间存储；FlashAttention 通过分块与优化访存避免完整物化该矩阵，但保留完整注意力的计算语义。[@FlashAttention]

自回归推理还有独立的缓存问题。在层数、KV 头数和精度固定时，KV cache 随已处理长度线性增长，单步解码访问的历史也越来越多。限制窗口可以控制成本，却会丢弃历史；StreamingLLM 进一步发现，直接移除初始 token 还可能破坏注意力分布。[@StreamingLLM]

### 训练与评估：长度增加不等于信息利用增加

长窗口需要有意义的长程训练信号。把互不相关的短文档拼接成一个长序列，虽然填满了窗口，却不一定提供跨文档推理或远距离检索的学习机会。已有数据分析也提醒我们，应分别观察文档长度分布和 token 长度分布。[@Harm2023longcontextrun]

评估时同样需要区分“语言建模仍然流畅”和“能够利用远处的信息”。[RoPE base 分析](https://arxiv.org/abs/2405.14591) 中，一些模型的 perplexity 相近，但有效检索范围存在明显差异。这意味着仅看平均 loss，可能高估模型的长上下文能力。
