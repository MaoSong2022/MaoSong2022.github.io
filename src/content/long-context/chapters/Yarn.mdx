### YaRN

YaRN（Yet another RoPE extensioN method）[@YaRN] 把分频段插值与 attention scaling 结合起来。理解它的设计，可以从 PI 如何压缩位置开始，再看 NTK 系列如何保留局部位置细节。

基于 $f_{W}(x_m, m, \theta_d)$, 作者统一了已有的扩展上下文长度的方法，作者将不同的扩展方法使用一个通用函数 $f_W(x_m,g(m), h(\theta_d))$  来表示，这里 $g(m)$ 和 $h(\theta_d)$ 分别代表了不同的长度外推方法所使用的变换。

#### Position Interpolation

Position Interpolation (PI) [@PI] 的核心思想在于，我们可以通过Interpolation，将超过预训练长度的文本给压缩到当前最大长度，以此来避免RoPE外推产生的问题，其对应的公式为

$$
f'_W(x_m,m,\theta_d) = f_W(x_m, \frac{mL}{L'}, \theta_d)
$$

其中 $L'>L$ 为我们扩展之后的上下文长度， $L$ 为我们预训练的上下文长度。使用通用函数表示的话，我们有

$$
g(m) = \frac{m}{s},\quad h(\theta_d) = \theta_d
$$

#### NTK-aware Interpolation

PI的问题是，并没有考虑不同维度的wavelength。
基于NTK理论，DNN当输入维度比较低，且embedding缺少高频内容时，模型就会很难学习到高频信息。对应到RoPE里面，输入的 token position id 是低维信息（1 维），而输出的RoPE是一个 $d$ 维的复杂向量。如果统一压缩位置差异，高频细节也会被削弱，从而影响模型区分内容相似、距离很近的 token。

因此，为了解决这个问题，作者对不同的维度使用了不同的缩放策略：**高频分量（较小的 $i$）缩放更少，低频分量（较大的 $i$）缩放更多。**

基于这个策略，作者提出了NTK-aware interpolation，其定义如下：

$$
g(m) = m, \quad h(\theta_{i,d}) = \theta'^{-2i/d}, i=0,\dots,(d-2)/2
$$

其中

$$
\theta' = \theta\cdot s^{\frac{d}{d-2}}
$$

这种方法保留了更多高频细节，但部分维度仍会外推到训练范围之外。论文中，不微调时 NTK-aware 优于 PI，而微调后的比较则可能相反；不能脱离训练设置判断两者的优劣。实际使用的缩放比例也可能大于目标长度比例。

> 上式的推导基于一个简单的假设：我们希望最后一个维度的wavelength在scaling之后，是线性变化的，即 $\lambda'_{(d-2)/2,d}=s\lambda_{(d-2)/2,d}$,  求解之后，我们就得到了上面的定义

PI 统一缩放所有频率，NTK-aware 通过修改 base 进行非均匀缩放，但两者都没有显式按照波长与训练长度的关系划分频段。这类不在乎wavelength的方法被称为**blind interpolation methods**, 接下来要介绍的就是基于wavelength的方法，即**target interpolation methods**.

#### NTK-by-parts Interpolation

NTK-by-parts 显式比较波长与训练上下文长度。低频分量的波长较长，在训练窗口内可能尚未旋转一周；高频分量旋转较快，对局部位置差异更敏感。如果把所有频率都压缩，近邻 token 的位置差异也会一起缩小。

因此，作者按频段分配插值强度：

1. 波长远小于训练长度的高频分量保持不变，保留局部位置细节。
2. 波长接近或超过训练长度的低频分量使用线性插值，避免继续外推。
3. 中间频段在两者之间平滑过渡。

作者定义了一个ratio $r$ 来描述原始上下文长度 $L$ 和 wavelength 之间的关系

$$
r(i,d) = \frac{L}{\lambda_{i,d}} = \frac{L}{2\pi\theta^{2i/d}}
$$

基于这个ratio，我们可以定义上面的三种处理方式对应的权重

$$
\gamma(r) = \begin{cases}
0, &\text{if } r < \alpha\\
1, &\text{if } r > \beta\\
\frac{r-\alpha}{\beta-\alpha}, &\text{otherwise}
\end{cases}
$$

其中， $\beta>\alpha>0$ 是超参数， $r<\alpha$ 对应低频分量的线性插值，$r>\beta$ 对应高频分量保持不变。这里按原始 base 计算波长，与下文实现使用的分段阈值相对应。

最后，NTK-by-parts interpolation的定义如下

$$
g(m) = m, \quad h(\theta_i) = \left(1-\gamma(r(i,d))\right)\frac{\theta_i}{s} + \gamma(r(i,d))\theta_i
$$

作者通过实验发现，在LLaMA上，$\alpha=1$ 和 $\beta=32$ 是一个比较好的选择

#### Dynamic NTK Interpolation

在实际中，一个经常遇到的场景就是sequence length会从1逐步上升到最大上下文长度，比如说inference的时候。对于这种情况，我们有两种解决方法：

1. 在整个inference周期中，RoPE的scaling factor都设置为 $s=L'/L$, 其中$L'$ 是扩展后的上下文长度
2. 在每次forward 的过程中，都更新scaling factor $s=\max(1, \ell'/L)$, 这里 $\ell'$ 是当前sequence的长度

作者发现，方案1在sequence长度小于 $L$的时候性能会下降，并且当上下文长度超过 $L'$ 时，性能下降的更快。
但是，方案2可以让模型的性能下降曲线更平缓。因此，作者将这种inference-time方法称为 **Dynamic Scaling method**, 当其与NTK-aware方法结合时，就得到了 **Dynamic NTK interpolation**

论文也考察了未经长上下文微调的模型。实现动态缩放时，需要保持历史 key 与当前 query 的 RoPE 缩放一致，不能只更新新 token 的频率而沿用旧缩放下的 KV cache。

#### Attention scaling：组成完整的 YaRN

在 NTK-by-parts 的基础上，YaRN 还在计算attention softmax时，加入了一个温度参数 $t>0$, 这样attention的计算就变成了

$$
\mathrm{Attn}(Q, K, V) = \mathrm{softmax}\left(\frac{QK^T}{t\sqrt{d}}\right)V
$$

作者发现，通过这种scaling的方式，YaRN可以在不改变代码的前提下，更改attention的机制。这种常数缩放可以并入 RoPE 的计算；但扩展序列本身仍会增加训练和推理成本

作者将YaRN定义为**结合了NTK-by-parts interpolation和上述scaling技巧的方法**

对于LLaMA，作者推荐使用如下参数：

$$
\sqrt{\frac{1}{t}} = 0.1\ln(s) + 1.
$$

#### YaRN 的实现与配置

以 Transformers v4.51.3 为例，YaRN 的实现在[HuggingFace/src/transformers/modeling_rope_utils.py](https://github.com/huggingface/transformers/blob/v4.51.3/src/transformers/modeling_rope_utils.py) 里的 `_compute_yarn_parameters` 函数里，其返回 `inv_freq` 以及 `attention_factor` 两个量，前者代表了 $\theta_d$, 后者是作用于 RoPE 的幅度系数 $\sqrt{1/t}$；同时缩放 query 和 key 后，attention logits 会乘以 $1/t$。下面保留计算频率与幅度的简化示意，不是完整的模型层实现。

```python
import math
import torch

def get_mscale(scale):
    if scale <= 1:
        return 1.0
    return 0.1 * math.log(scale) + 1.0

def find_correction_dim(num_rotations, dim, base, max_position_embeddings):
    """Inverse dimension formula to find the dimension based on the number of rotations"""
    return (dim * math.log(max_position_embeddings / (num_rotations * 2 * math.pi))) / (2 * math.log(base))

def find_correction_range(low_rot, high_rot, dim, base, max_position_embeddings):
    """Find dimension range bounds based on rotations"""
    low = math.floor(find_correction_dim(low_rot, dim, base, max_position_embeddings))
    high = math.ceil(find_correction_dim(high_rot, dim, base, max_position_embeddings))
    return max(low, 0), min(high, dim - 1)

def linear_ramp_factor(min, max, dim):
    if min == max:
        max += 0.001  # Prevent singularity

    linear_func = (torch.arange(dim, dtype=torch.float32) - min) / (max - min)
    ramp_func = torch.clamp(linear_func, 0, 1)
    return ramp_func


def yarn_parameters(dim, base, factor, original_max_position_embeddings,
                    beta_fast=32, beta_slow=1):
    pos_freqs = base ** (torch.arange(0, dim, 2) / dim)
    inv_freq_extrapolation = 1.0 / pos_freqs
    inv_freq_interpolation = 1.0 / (factor * pos_freqs)

    low, high = find_correction_range(
        beta_fast, beta_slow, dim, base, original_max_position_embeddings
    )
    extrapolation_weight = 1 - linear_ramp_factor(low, high, dim // 2)
    inv_freq = (
        inv_freq_interpolation * (1 - extrapolation_weight)
        + inv_freq_extrapolation * extrapolation_weight
    )
    attention_factor = get_mscale(factor)
    return inv_freq, attention_factor
```
