## Infra

SonicMoE [@SonicMoE] 和 LatentMoE [@LatentMoE] 基于 [roofline model](https://maosong.website/blog/performance-and-scalability/) 从 memory 和 communication 两个方面对 MoE 模型进行了分析.
与 [roofline model](https://maosong.website/blog/performance-and-scalability/) 一致，我们使用 $T_{\mathrm{mem}}$ 和 $T_{\mathrm{comm}}$ 分别代表 GPU 的内存访问 (HBM) 和 GPU 通信 (NVLink) 效率。
我们还假设负载均衡，即每个专家处理的 token 个数是一致的，使用与 [load balancing](#load-balancing) 相同的记号，则每个专家处理的 token 个数为 $BK/N$.
MoE module 我们使用 SwiGLU FFN.

### Memory Analysis

假设精度为 $p$, 则 expert 部分的计算开销为

$$
C_{\mathrm{exp}} = p * BK/N * 3 * d * d_{ff}
$$

单个 expert 的内存读/存数据包括 weights, inputs, activation, 总的内存访问量为

$$
M_{\mathrm{exp}} = p * 3 * d * d_{ff} + p * BK/N * d + p * (d+3m)
$$

其中，gate 和 up projection 的 activation 为 $p*2m$, SwiGLU 的 activation 为 $p*m$, down projection 的 activation 为 $p*d$.

因此 Arithmetic Density 为

$$
I = \frac{C_{\mathrm{exp}}}{M_{\mathrm{exp}}} = \frac{BK/N * 3 * d * d_{ff}}{3 * d * d_{ff}+BK/N * d+d+3m}
$$

### Communication Analysis

针对 MoE 模型的 infra 主要涉及 expert parallelism (EP), EP 将 MoE layer 的计算分为了三个阶段：

1. all-to-all dispatch: 基于 gating layer 的结果，将 token 通信传输到对应专家所在的 GPU 上
2. computation: 执行计算，即 $E_i(x)$.
3. all-to-all combine: 收集专家计算的结果，即 $y = \sum_{i=1}^K\mathrm{Normalize}(G_{e_i}(x)) E_{e_i}(x)$.
